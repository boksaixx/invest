5. https://aistudio.google.com 좌측 하단 **Plan/사용량** 메뉴에서 무료 등급(Free tier)이 아니라 종량제(Pay-as-you-go / Paid tier)로 표시되는지 확인

> ⚠️ **자주 헷갈리는 3가지가 실은 전부 다른 것입니다:**
> 1. **구글 원(Google One)의 제미나이 어드밴스드(Gemini Advanced) 구독** — 챗봇 앱 gemini.google.com을 쓰는 개인 구독입니다. 이 앱을 아무리 유료로 써도 **API 키 사용량과는 완전히 무관**합니다.
> 2. **API 키 자체의 유·무료 등급** — API 키는 무료로 "발급"되지만, 그 키가 연결된 Google Cloud 프로젝트에 **결제 계정이 연결·활성화**되어 있어야 비로소 더 넉넉한 유료 등급 한도로 호출됩니다. 위 4번 단계로 확인/등록하세요.
> 3. **구글 검색 그라운딩(google_search) 전용 쿼터** — 이 에이전트는 실시간 속보를 가져오기 위해 Gemini의 "구글 검색" 기능을 함께 씁니다. 이 기능은 일반 텍스트 생성과 **별도의, 더 빡빡한 자체 쿼터**를 씁니다. 즉 프로젝트가 유료 등급이어도 검색 그라운딩 호출만 429(쿼터 초과) 에러가 날 수 있습니다 — 텍스트 호출만 하는 자가진단(`/api/health`)이 "정상"으로 나와도 실제 뉴스 수집은 실패하는 경우가 바로 이 때문입니다. 반복적으로 429가 발생하면 Google Cloud 콘솔에서 해당 프로젝트의 "Generative Language API" 쿼터/한도 상향을 요청하세요.
>
> 이 에이전트는 429/401/403 오류가 뜨면 같은 요청을 반복해서 쿼터를 낭비하지 않도록 즉시 재시도를 중단하고 결과를 잠깐 캐시합니다(정상적인 보호 장치이며, 유료 등급 여부와 무관하게 항상 켜져 있습니다).

### 1단계. GitHub 설정 (자동 수집 에이전트 켜기)

1. 이 저장소(GitHub) 페이지 상단의 **Settings** 클릭
2. 왼쪽 메뉴에서 **Secrets and variables → Actions** 클릭
3. **New repository secret** 버튼을 눌러 아래를 추가 (DART는 키를 발급받았을 때만):
   - Name: `ANTHROPIC_API_KEY` / Secret: 아까 저장한 Claude 키 붙여넣기 → **Add secret**
   - Name: `GEMINI_API_KEY` / Secret: 아까 저장한 Gemini 키 붙여넣기 → **Add secret**
   - (선택) Name: `DART_API_KEY` / Secret: 아까 저장한 DART 인증키 붙여넣기 → **Add secret**
4. 저장소 상단 **Actions** 탭 클릭 → 초록색 **"I understand... enable them"** 버튼이 보이면 클릭
5. **Settings → Actions → General**에서 "Allow all actions and reusable workflows" + "Read and write permissions"가 선택되어 있는지 확인 (자동수집 데이터를 저장소에 커밋하려면 필요)
6. 왼쪽에서 **Trading Agent** 클릭 → 오른쪽 **Run workflow** 버튼 → 초록색 **Run workflow** 클릭 (첫 실행 테스트)

✅ 이제 평일 장중(09:00~15:30)엔 15분마다, 개장 전(08:30)·마감 후(16:10)엔 브리핑이 자동으로 돌아갑니다.
**밤 11시~아침 7시(KST)는 호출하지 않고, 주말은 일요일 저녁 1회만** 점검(+ 데이터 최신화)합니다 — 잠자는 시간에 API 비용이 새는 것을 막기 위한 설계입니다.
첫 실행 때 5개년 과거 데이터(주가/환율/해외지수)와 백테스트 통계도 자동으로 채워지고, 이후 매주 일요일마다 갱신됩니다.

### 2단계. Vercel 배포 (내 전용 앱 만들기)

1. https://vercel.com 접속 → **Sign Up** → **Continue with GitHub** 로 가입
2. **Add New... → Project** 클릭
3. 목록에서 **invest** 저장소 옆의 **Import** 클릭
4. **Environment Variables** 항목을 펼쳐서 아래 항목을 추가:
   - Key: `ANTHROPIC_API_KEY` / Value: Claude 키 붙여넣기
   - Key: `GEMINI_API_KEY` / Value: Gemini 키 붙여넣기
   - (선택) Key: `DART_API_KEY` / Value: DART 인증키 붙여넣기
   - Key: `APP_PASSWORD` / Value: 원하는 비밀번호 (생략하면 기본 비밀번호 `0815`가 자동 적용됩니다. 더 안전한 값으로 바꾸고 싶으면 원하는 문자열로 설정하세요)
5. **Deploy** 버튼 클릭 → 1~2분 기다리면 완료 🎉
6. 완료 화면의 주소(예: `https://invest-xxx.vercel.app`)를 누르면 앱이 열립니다. 비밀번호 입력 화면이 먼저 나오며, `APP_PASSWORD`를 따로 설정하지 않았다면 **`0815`** 를 입력하면 됩니다.
7. **휴대폰에 앱처럼 설치**: PWA(설치형 웹앱)로 만들어져 있어 진짜 앱처럼 설치할 수 있습니다.

## 🎯 오늘의 작전 — 장세 적응형 엔진

모드를 사람이 고르지 않습니다. **엔진이 그날 장세를 판별해 작전을 바꿉니다.** 목적은 모드 구분이 아니라 어떤 장에서든 대응하는 것이기 때문입니다.

| 레짐 | 판별 조건 | 그날의 작전 |
|---|---|---|
| **폭락장** | 간밤 SOX -3.5%↓ / 코스피 -3%↓ / 보유 종목 -7%↓ | 폭락 반등 소액 매수 + 패닉 매도 방지 지침 |
| **급등과열** | 종목 +12%↑ 급등 | 추격 금지 + 내일 +3% 지정가 분할 익절 |
| **변동성확대** | 과반 종목이 변동성 높음/극단 | σ비례 눌림목 지정가 매수 |
| **보통** | 그 외 | 평상시 원칙 (눌림목 + 개별 종목 판단) |

### 폭락장에서 실제로 뭐가 통했나 (5개년 실측)

대폭락장 대응은 이번 라운드의 핵심이라 **"피하기"가 아니라 "먹기"까지** 데이터로 검증했습니다.

**① 폭락 다음날은 통계적으로 반등했다**

| 지표 | 결과 (n=81, -8%↓ 폭락일) |
|---|---|
| 익일 종가 수익률 | 평균 **+1.4%** · 상승확률 65% |
| 최근 6개월 급변동장 | 평균 **+2.1%** · 승률 64% |
| 2일 후 누적 | 평균 +2.8% · 상승확률 67% |
| 익일 시가→저가 | 평균 -4.0% (**장중엔 반드시 더 빠진다**) |

→ 규칙: **폭락 마감 동시호가에 소액 매수 → 익일 종가 청산.** 거래비용 차감 후 5년 누적 +153.7%.
→ 익절/손절을 미리 거는 변형은 **오히려 열위**(+3% 익절은 급변동장 반등을 잘라먹고, -6% 손절은 장중 진폭에 먼저 걸림)라 쓰지 않습니다.
→ 단, **13.6% 확률로 다음날 또 -8% 폭락**한 전례가 있어 총자산 10% 이내 소액이 전제입니다.

**② 갭하락 아침의 패닉 매도는 손해였다**

간밤 SOX -3.5%↓였던 395일 실측:

| 지표 | 결과 |
|---|---|
| 당일 갭(시가) | 평균 **-2.4%** (89%가 갭하락) |
| 시가→종가 | 평균 +0.27% |
| 시가 매도 후 -3% 재매수 vs 그냥 보유 | **-0.13%p (무익)** |

→ **낙폭은 이미 갭에 반영돼 있습니다.** 시가 투매는 손실 확정일 뿐이라, 엔진은 폭락장에서 이 통계를 근거로 패닉 매도를 말립니다(손절선 원칙은 그대로).

**③ 상한가 근처 급등 다음날은 장중에 팔아야 했다**

| 지표 | 결과 (n=50, +12%↑ 급등일) |
|---|---|
| 익일 고가 | 평균 **+5.4%** (전일 종가 대비) |
| 익일 고가가 +3% 도달 | **64%** |
| 익일 갭하락 출발 | 42% |

→ 규칙: **내일 아침 +3% 지정가 분할 매도를 미리 걸어둘 것.** 시가 매도(평균 갭 +0.7%)보다 유리하고, 42%가 갭하락이라 전량 홀드는 금물입니다.

### 눌림목 규칙 (변동성확대/보통 장세)

폭락 직후 종목 제외 → 변동성 상위 종목 → **현재가 -0.6σ 지정가** → +1.0σ 익절 / -0.8σ 손절. 지정가 미체결이면 **그날은 매매 없음**(추격 금지).

| 기간 | 누적 | 승률 | 최대 낙폭 |
|---|---|---|---|
| 급변동장 전반 | +21.0% | 67% | 8.6% |
| 급변동장 후반 | +7.1% | 54% | 18.5% |
| 2025년 | +4.3% | 43% | 20.5% |
| 2024년(평온) | +10.7% | 48% | 17.2% |

### 📐 국면별 조건부 전망 — "평균"이 아니라 "지금과 같았던 때"

**여러 장세를 뭉갠 평균은 미래 판단 근거가 될 수 없습니다.** 예를 들어 "최근 6개월 보유 수익률 +63%"라는 숫자에는 코스피가 2배 오른 강세장과, 그 뒤 고점 대비 40~60% 무너진 붕괴 국면이 함께 들어 있습니다. 강세장이 만든 평균을 붕괴 국면에 적용하면 정확히 반대로 판단하게 됩니다.

그래서 엔진은 **지금과 같은 상태였던 과거 시점만 골라** 그 다음 20거래일에 실제로 무슨 일이 있었는지를 분포로 보여줍니다(`data/scenarios.json`, `npx tsx scripts/build-scenarios.ts` 로 갱신).

| 국면 | 표본 | 20일 후 중앙 | 하위 25% | 손실확률 | -20%↓ | +20%↑ |
|---|---|---|---|---|---|---|
| 안정상승추세 | 1,486 | +2.7% | -3.1% | 37% | 2% | 15% |
| 고변동상승추세 | 1,220 | +2.6% | -4.9% | 42% | 5% | 22% |
| 흔들리는상승 | 484 | +2.5% | -6.2% | 42% | 5% | 17% |
| **조정국면**(고점-20%↓) | 393 | **-1.7%** | -10.0% | **56%** | 8% | 15% |
| **고점붕괴초기**(고점-20%↓·변동성급등) | 314 | **-0.4%** | -8.6% | **52%** | 9% | 10% |

상승 국면(손실확률 37~42%)과 조정·붕괴 국면(52~56%)은 뚜렷하게 다릅니다. 폭락바닥권은 중앙값이 높지만 **26% 확률로 20% 넘게 더 빠졌고 표본이 23회뿐**이라 방향을 확정하는 근거로 쓸 수 없습니다 — 화면에도 그렇게 표시됩니다.

### 과거 통계가 담지 못하는 것

AI 업황 둔화 우려, 전쟁·지정학 리스크, 환율 급등, 국채금리 변동 같은 **구조적 리스크는 과거 가격 분포에 반영돼 있지 않습니다.** 5년 데이터에 없던 사건이 오면 위 확률은 그대로 빗나갑니다. 화면과 프롬프트 모두 이 한계를 함께 표시하며, 뉴스 레이어(Gemini)가 이런 이슈를 별도로 수집해 판단에 반영합니다.

### 정직하게 밝히는 한계### 정직하게 밝히는 한계

- **"매일 최소 5% 수익"은 어떤 규칙으로도 불가능합니다.** 5종목 중 1개 이상이 하루 5%+ 움직인 날은 96%로 기회는 거의 매일 있었지만, 그 기회를 순진하게 추격한 전략(변동성 1위를 시가 매수)은 6개월 **-54%** 였습니다.
- 고정 % 파라미터 최적화는 학습 +36% → 검증 **-5.5%** 로 뒤집혔습니다(과적합). σ비례를 쓰는 이유입니다.
- 위 성적은 과거 재현이며 미래 보장이 아닙니다. **최대 낙폭 -20% 구간을 견딜 수 있어야** 씁니다.
- 폭락 반등 규칙은 **시장 전체 패닉**에만 유효합니다. 개별 악재(회계·소송 등)에는 적용되지 않습니다.

모두 `npx tsx scripts/validate-modes.ts` 로 재현 가능합니다.

### 상관 비중 한도 — "나눠 담았다"는 착시 제거

기존 규칙은 **종목당** 최대 비중 50%였습니다. 그러면 삼성전자 50% + SK하이닉스 50% = 100%가
"분산"으로 통과됩니다. 두 종목의 상관은 최근 6개월 **0.89** — 사실상 한 종목입니다.

그래서 상관 0.7 이상인 쌍은 **합산 비중을 총자산의 50%로 제한**합니다(`lib/volatility.ts`의
`computeCorrelationCap`). 한도를 넘으면 신규/추가 매수 수량을 깎거나 아예 매수를 막고,
이미 넘긴 보유는 위험 카드에 경고로 표시합니다.

**검증 결과** (`npx tsx scripts/validate-correlation-cap.ts`, 2천만원 기준·나머지는 현금)

| 합산 비중 | 누적수익(6개월) | 일변동성 | 최악의 날 | 최대낙폭 | 위험대비수익 |
|---|---|---|---|---|---|
| 40% | +34.9% | 2.52% | -5.6% (-112만원) | 22.3% | 1.57 |
| 50% | +43.7% | 3.15% | -7.0% (-140만원) | 27.3% | 1.60 |
| 100% | +83.3% | 6.30% | -14.0% (-280만원) | 48.7% | 1.71 |

> **정직하게**: 위험대비수익이 한도를 바꿔도 거의 그대로입니다(1.57~1.71). 즉 이 한도는
> **수익을 개선하는 규칙이 아니라, 최악의 날을 견딜 수 있는 크기로 묶는 생존 규칙**입니다.
> 실측 상관은 5년 0.72 → 최근 1년 0.84 → 최근 6개월 0.89로, 급변동장일수록 더 붙습니다.

### 자동 감시주문 — 조건부로만 권합니다

확인 시간이 불규칙하다는 전제에서, 손절 예약주문을 "무조건 필수"로 만들지는 **않았습니다**.
데이터가 그렇게 말하지 않기 때문입니다.

**검증 결과** (`npx tsx scripts/validate-watch-orders.ts`, 5년·5종목, 엔진과 동일한 ATR 손절)

| 못 보는 기간 | 구분 | 건당 평균 | 최악 | -10% 넘는 손실 비율 |
|---|---|---|---|---|
| 1거래일 | 예약 있음 | -0.27% | -19.1% | 0.4% |
| 1거래일 | 예약 없음 | -0.26% | **-17.8%** | 0.5% |
| 5거래일 | 예약 있음 | +0.23% | **-20.0%** | **2.4%** |
| 5거래일 | 예약 없음 | +0.60% | -34.0% | 4.8% |

- **하루 이상 못 보면 예약이 꼬리를 자릅니다** — 최악 -34.0% → -20.0%, 큰 손실 비율 절반.
- **당일 안에 다시 볼 수 있으면 오히려 불리했습니다** — 스톱을 스치고 되돌아와 손해 본 건(94회)이
  실제로 손실을 줄여준 건(66회)보다 많았고, 최악도 -17.8% → -19.1%로 나빠졌습니다.
- 어느 경우든 **건당 평균 수익은 예약 쪽이 낮습니다**. 그래서 앱은 "예약을 걸면 더 번다"가
  아니라 **"하루 이상 자리를 비울 때 크게 잃지 않기 위한 보험"**으로만 안내합니다.
- 참고: 제안된 `-2% 손절 / +3% 익절` 같은 고정 % 파라미터는 채택하지 않았습니다. 이전 검증에서
  고정 % 방식은 학습구간 +36% → 검증구간 -5.5%로 뒤집혔습니다(과적합). σ(변동성) 비례 손절만
  네 구간 모두 견뎠습니다.

### 호가단위 — 화면의 가격은 전부 "실제로 주문 가능한 값"

배포 전 QA에서 발견해 고친 결함입니다. 계산 결과를 1원 단위로 반올림해 보여주고 있어서
삼성전자(호가 500원)에 `247,354원` 같은 값이 나왔습니다 — **증권사 앱에 입력 자체가 안 되는
숫자**였고, 5개 종목 전부 해당됐습니다. 미국 종목은 `Math.round()`가 센트를 통째로 날려
$195.04 종목의 손절가가 $183(실제 $182.65)으로 나왔습니다.

`lib/tick.ts`가 KRX 호가가격단위(2023년 통합 개정)와 미국 $0.01을 적용합니다. 방향도 구분합니다.

| 대상 | 반올림 방향 | 이유 |
|---|---|---|
| 손절가 | 올림 | 내리면 손절폭이 넓어져 실제 리스크가 계산치를 넘는다 |
| 목표가·익절가 | 내림 | 올리면 도달이 어려워져 제시한 계획보다 불리해진다 |
| 매수·매도 지정가 | 반올림 | 호가 한 칸은 가격의 0.2% 미만이라 모델 오차(σ)에 비해 무시할 수준 |

검증: 5종목 × 예상경로 전 구간 **335개 가격 전부 주문 가능**, 손익비 1:2 유지 확인.

### 팔라는 종목에 "이 값에 사면"을 띄우지 않습니다

같은 QA에서 발견한 문제입니다. 예상 경로 카드가 종목 상태와 무관하게 렌더링돼, 엔진이
`손절`·`전량매도`를 권하는 종목에도 파란색 **"이 값에 사면"** 카드가 크게 떠 있었습니다.
지금은 매도를 권하는 종목이면 매수 지정가와 매수 체결확률 열을 숨기고, 그 이유를 명시합니다.

### "표본을 10배로 늘리고 조합을 더 쪼개면 되지 않나?" — 이것도 측정했습니다

타당한 지적이라 세 가지로 검정했습니다 (`npx tsx scripts/validate-power.ts`).

**① 검정력 — 표본을 늘리면 답이 바뀌나**

| 표본 수 | AUC 표준오차 | 탐지 가능한 최소 우위 (적중률 환산) |
|---|---|---|
| 4,845 (현재) | 0.0083 | **51.9%** |
| 48,450 (10배) | 0.0026 | **50.6%** |
| 200,000 (40배) | 0.0013 | 50.3% |

표본을 10배로 늘려도 탐지 한계는 **√10 ≈ 3.2배**만 내려갑니다. 측정된 AUC 0.500은
"표본이 적어 못 잡은 것"이 아니라 **0에 매우 가깝다**는 뜻입니다. 게다가 10배를 모아서
겨우 잡아낼 0.6%p 우위는 **왕복 거래비용 0.25%를 빼면 남는 게 없습니다**.

**② 종목·시계를 최대로 넓히면**

종목 9개(국내 반도체 5 + 미국 대형 4) × 예측시계 5종으로 확대했습니다.
※ 겹치는 구간을 합쳐 표본 수만 부풀리지 않았습니다 — 그건 같은 정보를 여러 번 세는 것이라
신뢰구간만 가짜로 좁아집니다.

| 예측 시계 | AUC | 95% 신뢰구간 | 판정 |
|---|---|---|---|
| 1일 후 | 0.506 | 0.486~0.525 | 0.5 포함 → 신호 없음 |
| 2일 후 | 0.515 | 0.496~0.534 | 신호 없음 |
| 3일 후 | 0.513 | 0.494~0.532 | 신호 없음 |
| 5일 후 | 0.510 | 0.491~0.529 | 신호 없음 |
| **10일 후** | **0.530** | **0.511~0.549** | **약한 신호 있음** |

10일 시계에서만 신뢰구간이 0.5를 벗어났습니다. 다만 **이 앱은 단타용이라 10일은 시계가 맞지 않고**,
단일 분할 검증이라 워크포워드로 재확인이 필요합니다. 정직하게 기록만 남깁니다.

**③ 조합을 더 쪼개면 — 오히려 나빠졌습니다**

| 축 개수 | 국면 수 | 셀당 평균 표본 | 학습 적중 | 검증 적중 |
|---|---|---|---|---|
| 3축 | 27 | 194.3 | 53.4% | **50.2%** |
| 5축 | 213 | 24.6 | 54.4% | **49.3%** |
| 7축 | 923 | 5.7 | 52.4% | **48.3%** |
| 9축 | 2,602 | 2.0 | 50.7% | **48.2%** |

(검증구간 기저선 51.9% — 한쪽으로만 찍었을 때)

조합을 늘릴수록 **학습 성적만 오르고 검증 성적은 계속 떨어졌습니다.** 셀당 표본이
194개에서 2개로 붕괴하기 때문입니다. 어느 수준에서도 기저선을 넘지 못했습니다.
**변수와 조합을 더 넣는 것이 답이 아니라는 것이 실측 결과입니다.**

### 정성 변수는 정량 모델이 아니라 AI 판단 경로로 들어갑니다

트럼프 발언, 중동/이란 정세, 중국 반도체 업체 증설, 마이클 버리 등 큰손 포지션,
빅테크 CAPEX 가이던스, 실적 전망 — 이것들은 **과거 라벨이 없어 정량 모델에 넣을 수 없습니다.**
"트럼프가 관세를 언급한 과거 300일"을 라벨링한 데이터셋이 없기 때문입니다.

대신 실시간 뉴스(`lib/gemini.ts`)로 수집해 AI 판단 단계에 직접 투입합니다. 수집 주제를
11개로 확장하고 최소 건수를 강제했습니다.

- 중국 반도체 (SMIC·YMTC·CXMT 증설·수율·저가 공세·자급률 정책)
- 큰손 동향 (13F 공시, 공개 발언, 공매도, 연기금·국부펀드)
- 실적 전망 (추적 10종목 + TSMC·마이크론·ASML 가이던스)
- 지정학 (관세·수출규제 + 중동 정세와 유가·해운 영향)

AI에게는 **"이 요인들은 룰 엔진 점수에 들어가 있지 않다"**는 사실을 명시하게 하고,
그것이 점수를 어느 방향으로 보정해야 하는지 근거와 함께 밝히되 **통계가 아니라 해석임을
분명히 하라**고 지시했습니다. 반대로 뉴스에 없는 요인을 지어내는 것은 금지했습니다.

### 뉴스는 어떻게 숫자가 되나 — 수집과 전송을 분리했습니다

예전에는 뉴스를 20건 수집해 그중 10건만 Claude에 원문으로 넘겼습니다. 토큰을 아끼려던
선택이었는데, **몇 건 안 되는 뉴스로 시장 전체를 판단하는 쪽이 더 큰 위험**이었습니다.
그래서 "얼마나 모으는가"와 "얼마나 보내는가"를 분리했습니다.

| 단계 | 무엇을 | 비용 주체 |
|---|---|---|
| 수집 | 최대 **60건** (종목 뉴스 20건 상한, 나머지는 지수·업황·지정학·중국·큰손·실적·매크로) | Gemini |
| 집계 | 7개 축으로 나눠 건수·호재/악재·압력을 계산 (`lib/newsSignal.ts`) | 없음 (코드) |
| 전송 | 전체 집계 1줄 + 축별 7줄 + **원문 12건** | Claude |

**압력**은 기사마다 영향도(높음 3 / 중간 2 / 낮음 1)에 부호(호재 +, 악재 −)를 붙여
축별로 더한 뒤 건수로 나눈 값입니다. 음수면 악재 우위입니다.

| 축 | 무엇을 때리나 |
|---|---|
| 업황 | D램·낸드·HBM·현물가·가동률 → 반도체 5종목 전반 |
| 지정학 | 관세·수출규제·전쟁·중동·미중 → 10종목 전체 하방 (방산은 반대로 수혜 가능) |
| 중국 | SMIC·YMTC·CXMT 증설 → 메모리 2종목 마진 직격 |
| 실적 | TSMC·마이크론·ASML 가이던스 → 해당 밸류체인 종목 |
| 큰손 | 버핏·버리·13F·공매도·연기금 → 수급 심리 (방향 근거가 아님) |
| 매크로 | 금리·환율·유가·CPI·연준 → 금융·수출주 |
| 지수 | 코스피·나스닥·SOX·선물·VIX → 포지션 크기 조절 |

원문 12건은 앞에서 자르지 않습니다. **각 축에서 최소 1건씩 확보한 뒤** 남는 자리를
속보·고영향 순으로 채웁니다 — 앞에서 N건만 자르면 지정학 뉴스가 통째로 빠지는 날이 생기기 때문입니다.

**토큰 실측**

| 케이스 | 뉴스 블록 토큰 |
|---|---|
| 예전 (수집 20 / 원문 10건) | 667 |
| 현재 (수집 60 / 집계 + 원문 12건) | 930 |
| 현재 (수집 100 / 집계 + 원문 12건) | 938 |
| 만약 60건을 전부 원문으로 보냈다면 | 3,716 |

수집을 늘려도 전송 크기는 거의 고정입니다(60건 930 → 100건 938). 예전 대비로는 263토큰
늘었는데, 이는 축별 집계(138토큰)와 원문 2건 추가분입니다 — 수집을 3배로 넓히고 축 누락을
없애는 값으로는 싸다고 판단했습니다(10종목 전체 페이로드 5,795토큰의 15%).
축이 "무엇을 때리는지" 같은 고정 문구는 매번 보내지 않고 1시간 캐시되는 시스템 프롬프트에
넣어 재사용 시 1/10 비용으로 처리합니다.

**수집이 12건 미만이면** 집계에 "표본이 적어 오판 위험" 표시가 붙고, AI는 뉴스 근거의
비중을 낮추고 기술적·수급 근거를 앞세우도록 지시받습니다. 화면에도 같은 경고가 뜹니다.

**정직한 한계** — 이 집계는 "지금 무슨 일이 벌어지고 있나"의 요약이지 "그래서 몇 % 오른다"의
예측이 아닙니다. 뉴스 유형과 다음날 등락을 연결하려면 과거 뉴스를 전부 라벨링한 데이터가
필요한데 그런 자료가 없습니다. 그래서 이 압력 값으로 **새 점수를 만들지 않습니다.**

회귀 테스트: `npx tsx scripts/validate-news-parse.ts`
(수집 60건이 실제로 60건으로 남는지, 응답이 중간에 잘려도 살아남는지 검증)

### Claude API 비용 — 어디에 얼마가 나가나

**출력 토큰이 요금의 90%입니다.** 입력은 프롬프트 캐시(1시간 TTL)로 1/10 가격에 처리되지만,
응답 본문은 캐시가 없고 단가도 입력의 5배입니다. 그래서 비용 레버는 두 개뿐입니다 —
**모델 단가**와 **응답 길이**.

| 호출 | 모델 | 언제 | 빈도 |
|---|---|---|---|
| AI 정밀 분석 | **Sonnet 5** (`CLAUDE_MODEL`로 변경 가능) | 사용자가 버튼을 누를 때만 | 누른 만큼 |
| 자동수집 브리핑 | Haiku 4.5 (`CLAUDE_SUMMARY_MODEL`) | 장중 15분 간격 GitHub Actions | 하루 약 29회 |

**분석 1회 비용** (`npx tsx scripts/estimate-cost.ts`로 언제든 재계산):

| 모델 | 보통 날 | 많은 날 | 출력 단가 |
|---|---|---|---|
| Opus 4.8 (예전 기본값) | 약 183원 | 약 278원 | $25 / 100만 토큰 |
| **Sonnet 5 (현재 기본값)** | **약 110원** | **약 167원** | $15 / 100만 토큰 |
| Haiku 4.5 (참고) | 약 37원 | 약 56원 | $5 / 100만 토큰 |

Sonnet 5는 입력·출력 모두 Opus의 정확히 60% 단가라 **어떤 사용 패턴에서도 40% 절감**입니다.
하루 20번 누르면 월 7.7만원 → 4.6만원.

**왜 Opus가 아니어도 되나.** 이 앱에서 AI가 하는 일은 예측이 아닙니다. 변동성 추정, 도달 확률,
포지션 크기, 손절선, 국면 통계는 **전부 결정론적 룰 엔진이 계산**하고, AI는 그 결과를 뉴스·매크로와
교차검증해 쉬운 한국어로 옮기는 합성 작업만 합니다. 뒷단 분석 모델은 그대로 두고 앞단 번역기의
단가만 낮춘 것이라, 판단의 근거가 되는 숫자는 하나도 바뀌지 않습니다.

**품질이 아쉬우면** Vercel 환경변수에 `CLAUDE_MODEL=claude-opus-4-8`을 넣고 재배포하면 즉시
원복됩니다. `CLAUDE_THINKING=adaptive`로 사고를 켤 수도 있지만(품질↑) 사고 토큰이 출력 요금으로
청구되므로 비용이 늘어납니다 — 기본값은 사고 없음(예전 Opus 설정과 동일 조건)입니다.

**화면에서 직접 확인할 수 있습니다.** 분석 버튼 아래에 "이번 분석 약 ○○○원"이 뜹니다(길게 누르면
입력/출력 토큰 상세). 추정치를 믿는 대신 실제 청구 토큰으로 확인하세요.

> ⚠️ 앱 코드로는 API 과금 자체를 막을 수 없습니다.
> [console.anthropic.com/settings/billing](https://console.anthropic.com/settings/billing)에서
> **월 지출 한도(Spending limit)를 반드시 직접 설정**하세요.

### 계좌를 지키는 규칙 — 하루 손실 한도

이 앱에는 "1회 매매 리스크 = 총자산의 1%"라는 **건별** 한도만 있었습니다. 종목별로는 원칙을
지켜도 같은 날 여러 종목이 함께 무너지면 계좌 전체가 크게 빠집니다 — 반도체 5종목의 상관은
최근 6개월 0.89로, 사실상 한 종목에 몰아넣은 것과 같습니다.

**규칙**: 오늘 계좌가 총자산의 3%를 잃으면 그날은 신규 매수를 멈춥니다.
매도·손절 판단은 그대로 둡니다 — 멈춰야 하는 것은 "사는 것"이지 "빠져나오는 것"이 아닙니다.

**검증** (`npx tsx scripts/validate-daily-stop.ts`, 반도체 5종목 균등비중 1,229거래일)

| 한도 | 누적수익 | 최대낙폭 | 샤프 | 발동 |
|---|---|---|---|---|
| 없음(기존) | +632% | −52.0% | 1.16 | — |
| **−3%** | **+622%** | **−42.8%** | **1.25** | 75회 |
| −4% | +424% | −48.6% | 1.06 | 41회 |
| −5% | +439% | −51.2% | 1.07 | 27회 |
| −7% | +672% | −53.0% | 1.22 | 12회 |

−3%만 명확히 유효합니다. 누적수익은 거의 그대로인데 낙폭이 9.2%p 줄고 샤프가 올랐습니다.
한도를 느슨하게 잡으면(−4% 이상) 아무것도 막지 못합니다.

**견고성** — 기간을 4등분해도 4개 중 3개 구간에서 낙폭이 줄었고, **가장 크게 무너진 두 구간에서
개선폭이 가장 컸습니다**(+10.5%p, +13.9%p). 필요할 때 작동한다는 뜻입니다.

**정직한 한계** — 이 규칙은 **이미 발생한 오늘의 손실은 막지 못합니다**(손실이 난 뒤 발동하므로).
막는 것은 그 뒤에 이어지는 추격 매매·물타기입니다. 실제로 −3% 이하로 마감한 86일의
**다음날 승률은 50%, 최악은 −11.9%**로, "많이 빠졌으니 반등한다"는 근거가 없었습니다.
그리고 강세장에서는 수익을 깎습니다(2025~2026 구간 +427% → +343%). 위험 관리의 값입니다.

### 오늘 거래가 멈추는 지점 — 상하한가와 VI

국내 시장에는 가격이 특정 지점에 닿으면 거래 방식 자체가 바뀌는 구간이 있는데, 초보자는
이걸 모르고 주문을 걸어두었다가 "왜 체결이 안 되지"를 겪습니다. 종목마다 표시합니다.

| | 기준 | 의미 |
|---|---|---|
| 상한가·하한가 | 전일 종가 ±30% | 이 밖으로는 **아예 체결되지 않습니다** |
| 정적VI | 전일 종가 ±10% | 닿으면 약 2분간 단일가매매 — 호가창이 멈춥니다 |

표시되는 값은 전부 호가단위로 반올림해 실제 주문 가능한 값입니다.
AI가 상·하한가 밖의 가격을 제시하지 않도록 프롬프트에도 같은 정보를 넘깁니다.

**한계**: 동적VI(직전 체결가 대비 급변 시 발동)는 기준이 실시간 체결가라 15~20분 지연되는
무료 시세로는 계산할 수 없어 뺐습니다. 배당락·거래정지 해제일에는 거래소가 별도 기준가를
정하므로 그런 날은 증권사 화면을 우선하세요.

### 본전 가격 — "평단에 팔면 본전"이 아닙니다

국내 주식은 **팔 때만** 세금을 냅니다.

| 항목 | 요율 |
|---|---|
| 매도 시 세금 | 0.15% (2025년 이후 코스피·코스닥 공통) |
| 위탁수수료 | 0.015% × 2 (매수·매도 각각, 증권사별 편차) |
| **왕복 합계** | **약 0.18%** |

종목 카드에 "본전 가격(여기 넘겨야 이익)"을 표시하고, 목표가가 본전가보다 낮으면
그 매매는 이기고도 손해이므로 제안하지 않습니다. 세율은 정책에 따라 바뀌므로
실제 체결 내역과 다르면 `lib/engine.ts`의 `SELL_TAX_PCT`를 고치면 됩니다.

### 추천 성적표 — 이 앱이 맞았는지 확인합니다

앱이 조언만 하고 그 조언이 맞았는지 한 번도 확인하지 않는다면, 사용자는 앱을 믿어야 할지
판단할 방법이 없고 "왜 손해를 봤는가"(추천이 틀렸나 / 내가 안 지켰나)도 구분할 수 없습니다.

방향을 주장한 추천(매수·매도)만 기록하고 5거래일 뒤 판정을 확정합니다. 관망·보유는
방향 주장이 아니므로 채점하지 않습니다. 기록은 **이 기기 안에만** 저장됩니다.

**정직한 한계** — 이건 "내 수익률"이 아니라 **"앱 추천의 성적표"**입니다. 실제로 그대로
매매했는지는 앱이 모릅니다. 그리고 장중 고저가를 몰라 손절선을 스쳤다 되돌아온 경우가
빠지므로 **실제보다 좋게 나옵니다**. 표본 30건 미만에서는 실력과 운을 구분하지 못한다는
경고를 함께 표시합니다.

### 검토했으나 만들지 않은 것 (실측 근거)

- **슬리피지·호가잔량 모델** — 2천만원 전액을 한 종목에 넣어도 20일 평균 거래대금 대비
  삼성전자 0.000%, SK하이닉스 0.000%, 한미반도체 0.009%, **가장 작은 DB하이텍도 0.033%**입니다.
  이 규모에서 체결가를 밀어낼 일이 없어 모델을 만들 이유가 없습니다.
- **배당락 조정** — 추적 5종목 5년치에서 상하한가(±30%)를 넘는 일간 변동이 **0건**으로,
  액면분할·병합 같은 기업행위 미조정 흔적이 없습니다. 분기배당 배당락 갭은 0.3~0.5%로
  일간 σ 4.52% 대비 9% 수준이고 연 4회뿐이라 변동성 추정에 유의미한 영향이 없습니다.

### 숫자가 이상하면 보여주지 않습니다 — 안전 불변식

이 앱의 가격은 사용자가 **그대로 증권사에 입력하는 값**입니다. 그래서 "계산이 되긴 했다"로는
부족하고, "말이 되는 값인가"까지 통과해야 화면에 나갑니다.

실제로 있었던 사고 경로입니다. 외부 시세 API가 잘못된 현재가(0, `null`, 캔들 이력과 자릿수가
다른 값)를 돌려주면 → ATR 기반 손절가가 음수로 계산되고 → 화면에 **"손절 -35,062원"** 으로 떴습니다.
초보 사용자는 그 숫자로 주문을 넣습니다.

방어선을 세 겹으로 두었습니다.

| 층 | 무엇을 막나 |
|---|---|
| `lib/market.ts` | 야후가 준 현재가가 유한·양수가 아니면 **시세 없음**으로 내려보낸다 (네이버 경로에만 있던 검사를 야후에도 추가) |
| `lib/engine.ts` | 파생 가격(손절·목표·진입)이 유한·양수가 아니거나 현재가의 2배 밖이면 **null**로 비우고 경고를 남긴다 |
| `app/page.tsx` | 표시 단계에서 음수·`Infinity`는 `-`로 표시한다 (예전에는 `-35,062원`, `∞원`으로 그대로 렌더링됐다) |

`/api/advice`도 클라이언트가 보낸 포트폴리오를 신뢰하지 않고 정규화합니다. localStorage가
부분 저장되거나 손상되면 `holdings`가 문자열이거나 추적 목록에 없는 종목일 수 있는데,
그대로 두면 500 에러와 내부 `TypeError`가 사용자에게 그대로 노출됐습니다.

**자동수집이 멈추면 그렇다고 말합니다.** 예전에는 헤더에 `자동수집 14:10`처럼 시:분만 떠서
3일 전 데이터도 오늘 것으로 읽혔습니다. 지금은 경과 시간을 명시하고(`5시간 전`), 2시간을 넘으면
빨간색으로, **24시간을 넘으면 매수 매력도 자체를 숨깁니다** — 어제 점수로 오늘 주문하는 일을 막습니다.

회귀 테스트: `npx tsx scripts/validate-safety.ts`
(캔들 0~60개, 현재가 0·음수·NaN·∞, 현금 0, 무변동, 상한가, 10종목 × 폭락장 — 총 30여 가지 조합에서
모든 불변식을 검사합니다)

### "오늘 오를 확률"에 대한 답 — 세 번 만들고 세 번 실패했습니다

이 앱이 가장 자주 받는 질문이고, 답하려고 서로 다른 방식으로 **세 번** 모델을 만들었습니다.

| 시도 | 방식 | 결과 |
|---|---|---|
| ① | 유사패턴 kNN (단일 시간대 10특징, 5,845 패턴) | 적중률 **47.4%** — 기준선 54.2% 미달 |
| ② | 다중 시간대 로지스틱 (13특징, 4,845 표본) | Brier **0.2506** — 기저율과 **완전히 동일**, AUC **0.500** |
| ③ | 국면 조건부 (21개 국면) | 다중검정 보정 후 유의미한 국면 **0개** |

②는 "모델이 단조로워서 실패한 것 아니냐"는 지적을 검증하려고 만들었습니다.
**3일 · 1주 · 2주 · 1개월 · 6개월 · 3년** 수익률에 변동성 국면·낙폭·이격도·RSI·거래량·
간밤 SOX·전일 코스피까지 넣었는데, Brier score가 "항상 평균만 말하는 모델"과 소수점 넷째 자리까지
같았습니다. AUC 0.500은 오른 날과 내린 날을 **전혀 구분하지 못한다**는 뜻입니다.

로지스틱 계수도 전부 |0.03~0.06|으로 미미했고, 부호도 직관과 어긋났습니다(전일 코스피가 오르면
다음날 하락 쪽). 즉 신호가 아니라 잡음입니다.

> **결론**: 모델링 방식의 문제가 아니라, 이 종목군의 다음날 방향이 예측되지 않습니다.
> 그래서 앱은 "오를 것 같다"를 **말하지 않습니다**.

**대신 보여주는 것** — 국면별 과거 실측 상승률 (`lib/upRate.ts`)

종목 카드에 이렇게 뜹니다.

```
오늘 상승 확률  45.2%     전체 평균 48.5%
고변동/붕괴/횡보 국면 · 과거 104일 실측.
전체 평균과 통계적으로 구분되지 않습니다 — 오늘 방향은 사실상 동전던지기입니다.
방향이 아니라 얼마에·얼마나·어디서 자를지로 판단하세요.
```

숫자를 지어내지 않고 **과거에 실제로 몇 %가 올랐는지**만 보여주며, 그 값이 전체 평균과
통계적으로 구분되는지를 함께 표시합니다. 거의 모든 국면에서 답은 "구분되지 않는다"이고,
**그 사실 자체가 가장 중요한 투자 정보**입니다 — 방향에 베팅할 근거가 없다는 뜻이니까요.

**그래서 앱이 집중하는 것** (전부 실측 검증됨)

| 질문 | 앱의 답 | 검증 |
|---|---|---|
| 얼마에 살까 | 지정가 후보 + 체결 확률 | 2,495일 실측표 |
| 얼마나 살까 | 리스크 1% 규칙 수량 (σ 비례) | 변동성 90% 구간 적중 88% |
| 어디서 자를까 | ATR 손절선, 손익비 1:2 | 감시주문 실측 (최악 -34%→-20%) |
| 얼마나 움직일까 | 시간대별 상·하단 밴드 | D+1~D+3 구간 적중 88.3~89.4% |

### (구버전 기록) 방향 예측 1차 시도

"오늘 오를까 내릴까"를 예측하는 모델을 실제로 만들어 검증했습니다. 기상청 아날로그 기법처럼
지금 상태를 10개 변수로 벡터화하고(전일 등락·3일/5일 누적·RSI·낙폭·이격도·변동성 분위·거래량Z·
간밤 SOX·ADX), 과거 **5,845개 패턴** 중 가장 닮은 120건을 찾아 그 다음날 결과로 방향을 냈습니다.

**결과 (`npx tsx scripts/validate-analog.ts`, 워크포워드·미래정보 미사용)**

| 항목 | 값 |
|---|---|
| 방향 적중률 | **47.4%** |
| 기준선(다수쪽 고정) | 54.2% |
| 그대로 따라갔을 때 | **매일 평균 -0.16%** |
| 확신도 60~65% 구간 적중률 | 40.0% (확신할수록 더 틀림) |

이웃 수·인접일 제외·평가기간을 바꿔 5가지 설정으로 재검증해도 결론은 같았습니다
(최대 3,431표본에서 50.4% vs 기준선 51.7%). **구현 결함이 아니라 다음날 방향이 예측되지 않는 것**입니다.

> 그래서 이 앱은 "오를 것 같다/내릴 것 같다"를 말하지 않습니다. 실패 기록은 앱의 `분석 방식` 탭에
> 그대로 공개해 두었습니다.

### 대신 제공하는 것 — 도달 확률 (지정가가 체결될까)

단타에서 실제로 필요한 판단은 "오를까?"가 아니라 **"내가 건 지정가에 닿을까?"**입니다.
이건 방향이 아니라 변동폭의 문제이고, 변동폭은 검증된 모델이 잘 맞힙니다(90% 구간 적중 88%).

**검증 결과** (`npx tsx scripts/validate-touch.ts`, 2,495일 실측 → `data/touch-stats.json`)

| 거리 | 이론값(반사원리) | 실측 하단 도달 | 실측 상단 도달 |
|---|---|---|---|
| 0.5σ | 61.7% | 46.9% | 53.6% |
| 0.75σ | 45.3% | 32.6% | 39.5% |
| 1.0σ | 31.7% | 22.6% | 28.6% |
| 2.0σ | 4.6% | 4.6% | 8.3% |

이론값이 실제보다 20%가량 높아(하루 한 세션만 열리고 갭으로 시작하는 실제 시장과 연속 랜덤워크
가정의 차이) **실측표를 그대로 씁니다**. 상단 도달률이 하단보다 일관되게 높은 건 국내 반도체주의
상방 꼬리가 더 두껍기 때문이며(상한가 현상), 앱은 이 비대칭을 평균으로 뭉개지 않고 따로 씁니다.

앱은 이걸 두 가지로 보여줍니다.
- **지정가 후보**: "이 값에 사면 / 이 값에 팔면" + 마감까지 닿을 확률 (0.75σ 거리 기준)
- **시간대별 표**: 30분 단위 예상 상·하단 금액과, 그 지정가에 **그 시각까지 한 번이라도 닿을 누적 확률**
  (10:00 조회 시 13:00까지 21% → 마감까지 33% → 다음 거래일까지 47%처럼 시간이 갈수록 올라갑니다)

### 예상 경로 차트 — 글 대신 그림으로

"예상 등락 -11.7% ~ +14.2%"라는 문장은 초보자가 감을 잡기 어렵습니다. 그래서 같은 추정을
**조회한 그 시각부터 오늘 마감 → 다음 거래일 → 2거래일 뒤**까지의 확률 구간으로 그립니다
(`lib/forecastPath.ts` 계산 → `app/ForecastChart.tsx` 렌더).

- 폭은 위 변동성 모델의 σ와 경험분위수를 그대로 씁니다. 불확실성은 시간에 비례해 쌓이므로 폭은 **√시간**으로 벌어집니다.
- 하루 안에서는 개장 직후·마감 무렵이 크고 점심때가 작은 **U자 분산 배분**을 씁니다. 그래서 15:20에 조회하면 "오늘 변동폭 4% 남음"처럼 남은 몫이 작다는 게 바로 보입니다.
- 중앙선은 예측이 아니라 "제자리 + 과거 같은 국면의 아주 약한 평균 흐름"(하루 ±0.5% 제한)입니다.
- 손절가·목표가를 같은 축에 겹쳐 그려서 **손절선이 하루 정상 변동폭 안에 있는지**를 눈으로 확인할 수 있습니다.

**검증 결과** (`npx tsx scripts/validate-forecast-path.ts`)

| 구간 | 90% 띠 실제 적중 | 50% 띠 실제 적중 | 표본 |
|---|---|---|---|
| 다음 거래일 | 88.3% | 48.0% | 1,235 |
| 2거래일 뒤 | 89.4% | 44.8% | 1,235 |
| 3거래일 뒤 | 88.6% | 45.5% | 1,235 |

√시간 가정의 실측 비율(실제 h일 변동성 ÷ 이론값)은 0.87~1.04로, 랜덤워크 가정이 이 종목군에서 대체로 성립합니다.

**한계**

- 안쪽 50% 띠는 표시보다 살짝 좁게 잡힙니다(하루 기준 분위수를 여러 날에 그대로 쓰기 때문). 앱의 `분석 방식` 탭에도 이 숫자를 그대로 공개합니다.
- 장중 U자 배분은 자체 수집 로그 표본이 20건뿐이라 **실측이 아니라 통상적으로 관찰되는 표준 형태**입니다. 그래서 장중 부분구간은 일 단위만큼 검증되지 않았습니다.
- 주말·공휴일에는 장중 구간을 그리지 않고 거래일 단위만 표시합니다.
- 이 데이터는 **Claude 프롬프트에 넣지 않습니다** — 순수 파생값이라 토큰을 쓸 이유가 없습니다(차트 추가 토큰 비용 0).

> **채택하지 않은 변수**: VIX는 이론상 선행지표지만 실측 기여도가 0이어서 넣지 않았습니다. GARCH(1,1)는 EWMA보다 열위였습니다. 2요소·비대칭 모델은 복잡도만 늘고 개선이 없어 버렸습니다.

**한계 (정직하게)**

- 90% 구간 적중률이 목표보다 1~2%p 낮습니다. 원인은 **레짐 전환 시점**입니다 — 조용하던 종목이 갑자기 급등락하기 시작하는 첫날은 어떤 사후 관측 모델도 맞히지 못합니다. 그래서 경계값은 보수적으로 해석하세요.
- 상방 초과(6.8%)가 하방 초과(4.5%)보다 많습니다. 지금은 급등 쪽 꼬리가 더 두꺼운 국면이라, 성급한 매도나 공매도가 특히 불리합니다.
- 확정 예측이 아니라 "이 정도 범위는 각오해야 한다"는 기준입니다.

**포트폴리오 위험 (내 계좌 금액 기준)**

종목별 %가 아니라 **내 돈이 하루에 얼마나 흔들리는지**를 원 단위로 보여줍니다. 이때 종목 간 상관관계를 반영하는 것이 핵심입니다 — 실측상 삼성전자와 SK하이닉스의 상관계수는 **0.86**으로, 둘을 나눠 담아도 분산 효과가 거의 없습니다.

- 3종목에 균등 분산해도 **실질 독립 종목수는 약 1.2개** (사실상 한 종목 베팅)
- 종목별 위험을 단순히 더하면 실제 위험을 **53% 과소평가**

## ❓ 자주 묻는 질문

**Q. 자동으로 주식을 사고 파나요?**
아니요. 이 에이전트는 **조언만** 합니다. 실제 매매는 본인이 증권사 앱(MTS)에서 직접 합니다. 자동 매매는 증권사 API 인증·법적 요건이 필요해 의도적으로 제외했습니다.

**Q. 비용이 얼마나 드나요?**
GitHub Actions·Vercel은 무료 한도로 충분합니다. **Gemini**는 자동 수집(15분 간격, 하루 약 27회)만 실제로 호출하고 — 화면에서 "AI 정밀 분석"을 눌러도 그 결과가 20분 이내로 신선하면 그대로 재사용하고 새로 호출하지 않습니다 — 프롬프트도 짧게 유지했고(수집은 최대 60건이지만 Claude로는 집계+12건만 넘어가므로 Claude 토큰은 거의 고정) 가장 저렴한 flash-lite/flash 모델을 우선 사용하므로, 소액(만 원 안팎) 충전으로도 상당 기간 충분합니다. 다만 정확한 소진 속도는 실제 사용 패턴에 따라 다르니, https://aistudio.google.com 좌측 하단 **사용량/결제** 메뉴에서 주기적으로 잔액을 확인하세요. **Claude API**는 사용량 과금입니다. 자동수집은 저렴한 Haiku 4.5로 장중 15분 간격 + 개장전/마감 브리핑만 돌고 밤 11시~아침 7시·평일 외에는 호출하지 않아 월 $2~4 수준입니다. 화면에서 누르는 "AI 정밀 분석"은 **Sonnet 5** 기준 1회 약 110~167원이라, 하루 10번이면 월 2.3만원입니다(자세한 내역은 위 "Claude API 비용" 절, `npx tsx scripts/estimate-cost.ts`로 재계산 가능). 분석 버튼 아래에 이번 호출의 실제 비용이 표시됩니다. 다만 이는 예상치이며 실제 사용 패턴에 따라 달라질 수 있으니, [console.anthropic.com/settings/billing](https://console.anthropic.com/settings/billing)에서 **월 지출 한도(Spending limit)를 직접 설정**해두는 것을 강력 권장합니다 — 앱 코드로는 API 자체의 과금을 막을 수 없기 때문입니다.

**Q. 시세가 실시간인가요?**
추적 10종목(반도체 5 + 비반도체 5)의 개별 시세는 네이버 금융의 실시간 폴링 API를 우선 사용해 지연이 짧은 편입니다(네이버가 실패할 때만 야후로 폴백). 코스피·나스닥·SOX·환율 등 **매크로/해외지수도 야후 파이낸스 API를 쓰기 때문에 최대 15~20분 지연**될 수 있습니다. 화면에 시세 옆 "n분 전 시세"로 표시됩니다. 어느 경우든 증권사 실시간 호가·체결과 완전히 같지는 않으니, 실제 주문 직전에는 반드시 증권사(국내/해외) 앱에서 최신가를 확인하세요. 이 한계 때문에 진입/무효화 조건을 고정 가격이 아니라 "조건 충족 여부"로 설계했지만, 완전한 실시간 체결가는 증권사 API 인증 없이는 얻을 수 없어 완전히 없앨 수는 없습니다.

**Q. 알림(카카오톡 등)은 없나요?**
현재는 없습니다. 자동수집은 장중 15분 간격으로 데이터만 쌓고, 실제 조언은 앱에서 버튼을 눌러야 받을 수 있습니다. 장중에는 주기적으로 앱을 열어 확인하는 것을 권장합니다.

**Q. 자동 수집 데이터는 어디에 쌓이나요?**
이 저장소의 `data/` 폴더에 자동 커밋됩니다. `data/latest.json`(최신), `data/log/날짜.json`(일별 기록), `data/market-history.json`(5개년 주가/환율/지수), `data/backtest.json`(백테스트 통계, 매주 갱신)입니다.

**Q. 앱 분석과 자동 수집의 차이는?**
자동 수집(장중 15분 간격)은 시장 전체 관점의 신호와 뉴스를 축적하고, 앱에서 버튼을 누르면 **내 보유 현황을 반영한** 맞춤 분석이 그 자리에서 실행됩니다.

**Q. 백테스트는 얼마나 믿을 수 있나요?**
룰 엔진의 일봉 기술적 점수가 68점 이상이었던 과거 시점을 찾아 5/10거래일 후 종가 수익률을 집계한 **단순 참고 통계**입니다. 장중 변동성·뉴스·매크로는 과거 시점으로 재현할 수 없어 제외했고, 실제 체결가·슬리피지·거래비용도 반영하지 않았습니다. "과거 승률 OO%"는 통계적 경향일 뿐 다음 매매의 결과를 보장하지 않습니다 — 화면과 AI 판단 모두 이 통계를 절대적 근거로 쓰지 않고 참고 지표로만 언급하도록 설계했습니다.

**Q. 코드를 수정하면 어떻게 반영되나요?**
GitHub에서 파일을 수정(커밋)하면 Vercel이 자동으로 다시 배포합니다. 별도 조작이 필요 없습니다.

## ⚠️ 알려진 한계 (정직하게 밝힙니다)

- **비밀번호는 반드시 직접 설정하세요**: `APP_PASSWORD` 환경변수를 지정하지 않으면 기본 비밀번호로 동작하는데, 그 값은 이 공개 저장소 코드에 그대로 적혀 있어 실질적인 보호가 되지 않습니다(주소를 아는 사람이 보유 종목·수량을 볼 수 있고 API 크레딧도 소모시킬 수 있습니다). 기본값으로 돌고 있으면 앱 첫 화면에 경고 배너가 뜨고 `/api/health`에도 ❌로 표시됩니다. Vercel → Settings → Environment Variables에서 `APP_PASSWORD`를 추가한 뒤 Redeploy 하세요.
- **자동수집이 멈추면 판단 근거가 낡습니다**: GitHub Actions가 실패하면 뉴스·마스터 스코어가 갱신되지 않습니다. 헤더에 경과 시간이 표시되고 24시간이 넘으면 매수 매력도를 숨기지만, 근본 해결은 Actions 탭에서 워크플로 실패 원인을 확인하는 것입니다.
- **시세 지연**: 추적 10종목은 네이버 실시간 API를 우선 써서 지연이 짧은 편이지만, 매크로/해외지수(코스피·나스닥·SOX·환율·유가 등)는 야후 무료 API 특성상 최대 15~20분 지연 가능합니다. 어느 쪽도 증권사 실시간 호가·체결 데이터는 아닙니다.
- **반도체 전용 통계의 적용 범위**: 국면별 과거통계·간밤 SOX 전이 보정·폭락반등/급등익절 플레이북은 국내 반도체 5종목으로 실측해 만든 값이라 **반도체 종목에만** 적용됩니다. 비반도체 5종목에는 그 숫자를 끌어다 쓰지 않고, 해당 종목 자체의 변동성·기술적 지표·수급·업종 뉴스로만 판단합니다.
- **급등락 표시 안전장치**: 지수·환율 등의 등락률이 상식적으로 불가능한 수준(예: 지수가 하루 10% 이상)으로 계산되면, 데이터 오류로 간주해 등락률을 0%로 보정하고 서버 로그에 경고를 남깁니다(잘못된 급등락을 그대로 보여주는 것보다 안전). 다만 이 안전장치가 실제로 발생 가능한 극단적 이벤트(예: VIX 급등)까지 지우지 않도록 종류별로 다른 상한선을 적용했습니다.
- **분석 소요 시간**: AI 정밀 분석은 30초~2분이 걸립니다. 그 사이 가격이 움직일 수 있어, 결과는 고정가가 아니라 조건부 트리거 중심으로 제시됩니다.
- **백테스트는 단순 재현치**: 5개년 일봉 종가만으로 재현한 참고 통계이며, 장중 변동성·뉴스·매크로·거래비용·슬리피지는 반영하지 않았습니다. 과거 승률이 미래 수익을 보장하지 않으며, 검증된 필승 전략이 아니라 확률적 우위를 노리는 참고 지표입니다.
- **공휴일 인식 제한**: 양력 고정 공휴일(신정·삼일절 등)만 자동 인식합니다. 설날·추석 등 음력 공휴일 주간은 별도로 확인하세요.
- **비밀번호는 정식 인증이 아님**: 기본값(`0815`) 또는 직접 설정한 `APP_PASSWORD` 값 하나로 여닫는 단일 비밀번호 게이트일 뿐, 계정별 권한 관리나 무차별 대입 공격 방어 같은 정식 인증 시스템이 아닙니다. 배포 주소를 다른 사람과 공유하지 말고, 가능하면 `APP_PASSWORD` 환경변수를 본인만 아는 값으로 바꾸는 것을 권장합니다.
- **공포탐욕지수**: 미국 시장(CNN) 기준 지표이며 비공식 데이터 소스라 수집이 실패할 수 있습니다(실패 시 조용히 생략).
- **외국인/기관 수급은 실시간이 아니라 전일까지 확정된 EOD 데이터**: KRX 공식 공개 데이터를 쓰지만, 장중 실시간 체결 기준 수급(초 단위로 바뀌는 수급 주체별 매매)까지는 증권사 API 인증 없이는 가져올 수 없어 제외했습니다. "전일 기준"이라는 점을 감안해서 참고하세요. 데이터를 못 가져온 종목은 거래량Z점수(거래량 급증 여부)로 대신 설명합니다. KRX 공개 엔드포인트는 공식 문서화된 API가 아니라 리버스 엔지니어링된 방식이라, 사용 중 예고 없이 응답 형식이 바뀌면 해당 종목만 조용히 "데이터 없음"으로 처리됩니다(에러로 앱이 멈추지 않음).
- **DART 공시 sentiment는 제목 키워드 기반 단순 분류**: 공시 본문 전체를 분석하는 것이 아니라 "유상증자"·"자기주식취득" 같은 제목 키워드로만 긍/부정을 1차 분류합니다. 최종 해석은 Claude가 맥락을 더해 판단하지만, 애매한 공시는 반드시 원문 링크를 눌러 직접 확인하세요.
