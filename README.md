### 준비물: API 키 (필수 2개 + 선택 1개)

**① Claude API 키** (AI 분석 담당, 유료 — 사용량만큼 과금)

2. 왼쪽 메뉴 **API Keys** → **Create Key** 버튼 클릭

4. **Billing** 메뉴에서 결제 카드 등록 (월 $5~10 정도면 충분합니다)
> ⚠️ claude.ai 유료 구독(Pro/Max)과 API 결제는 **완전히 별개**입니다. claude.ai 구독이 있어도 API는 별도로 크레딧을 충전해야 동작합니다.

**② Gemini API 키** (뉴스 수집 담당 — 구글 검색 그라운딩 사용)
1. https://aistudio.google.com/apikey 접속 → 구글 계정 로그인
2. **API 키 만들기** 버튼 클릭 (기존 키가 있으면 그대로 사용해도 됩니다)
3. 나온 `AIza...` 로 시작하는 문자를 복사해서 메모장에 저장
4. 만든 키가 어느 **Google Cloud 프로젝트**에 연결됐는지 확인 → https://console.cloud.google.com/billing 에서 그 프로젝트에 **결제 계정(Billing Account)이 연결되어 있는지** 확인. 연결이 안 돼 있으면 "결제 계정 연결" 버튼으로 카드 등록
5. https://aistudio.google.com 좌측 하단 **Plan/사용량** 메뉴에서 무료 등급(Free tier)이 아니라 종량제(Pay-as-you-go / Paid tier)로 표시되는지 확인

> ⚠️ **자주 헷갈리는 3가지가 실은 전부 다른 것입니다:**
> 1. **구글 원(Google One)의 제미나이 어드밴스드(Gemini Advanced) 구독** — 챗봇 앱 gemini.google.com을 쓰는 개인 구독입니다. 이 앱을 아무리 유료로 써도 **API 키 사용량과는 완전히 무관**합니다.
> 2. **API 키 자체의 유·무료 등급** — API 키는 무료로 "발급"되지만, 그 키가 연결된 Google Cloud 프로젝트에 **결제 계정이 연결·활성화**되어 있어야 비로소 더 넉넉한 유료 등급 한도로 호출됩니다. 위 4번 단계로 확인/등록하세요.
> 3. **구글 검색 그라운딩(google_search) 전용 쿼터** — 이 에이전트는 실시간 속보를 가져오기 위해 Gemini의 "구글 검색" 기능을 함께 씁니다. 이 기능은 일반 텍스트 생성과 **별도의, 더 빡빡한 자체 쿼터**를 씁니다. 즉 프로젝트가 유료 등급이어도 검색 그라운딩 호출만 429(쿼터 초과) 에러가 날 수 있습니다 — 텍스트 호출만 하는 자가진단(`/api/health`)이 "정상"으로 나와도 실제 뉴스 수집은 실패하는 경우가 바로 이 때문입니다. 반복적으로 429가 발생하면 Google Cloud 콘솔에서 해당 프로젝트의 "Generative Language API" 쿼터/한도 상향을 요청하세요.
>
> 이 에이전트는 429/401/403 오류가 뜨면 같은 요청을 반복해서 쿼터를 낭비하지 않도록 즉시 재시도를 중단하고 결과를 잠깐 캐시합니다(정상적인 보호 장치이며, 유료 등급 여부와 무관하게 항상 켜져 있습니다).

> 💰 **Gemini는 소액 충전으로 충분합니다.** 자동 수집(15분 간격)만 실제로 Gemini를 호출하고, 화면에서 "AI 정밀 분석"을 누를 때는 그 자동 수집 결과가 20분 이내로 신선하면 그대로 재사용합니다(사용자가 여러 번 눌러도 Gemini를 중복 호출하지 않음). 호출당 프롬프트도 짧게, 응답도 뉴스 15건·문장당 60자 이내로 압축해 토큰을 아낍니다. 모델도 비용이 가장 낮은 flash-lite/flash 계열을 항상 먼저 시도하고, pro 계열은 나머지가 전부 실패했을 때만 최후 수단으로 씁니다.

### 1단계. GitHub 설정 (자동 수집 에이전트 켜기)

1. 이 저장소(GitHub) 페이지 상단의 **Settings** 클릭
2. 왼쪽 메뉴에서 **Secrets and variables → Actions** 클릭
3. **New repository secret** 버튼을 눌러 아래를 추가 (DART는 키를 발급받았을 때만):
   - Name: `ANTHROPIC_API_KEY` / Secret: 아까 저장한 Claude 키 붙여넣기 → **Add secret**
   - Name: `GEMINI_API_KEY` / Secret: 아까 저장한 Gemini 키 붙여넣기 → **Add secret**
   - (선택) Name: `DART_API_KEY` / Secret: 아까 저장한 DART 인증키 붙여넣기 → **Add secret**
4. 저장소 상단 **Actions** 탭 클릭 → 초록색 **"I understand... enable them"** 버튼이 보이면 클릭
5. **Settings → Actions → General**에서 "Allow all actions and reusable workflows" + "Read and write permissions"가 선택되어 있는지 확인 (자동수집 데이터를 저장소에 커밋하려면 필요)
6. 왼쪽에서 **Trading Agent** 클릭 → 오른쪽 **Run workflow** 버튼 → 초록색 **Run workflow** 클릭 (첫 실행 테스트)

✅ 이제 평일 장중(09:00~15:30)엔 15분마다, 개장 전(08:30)·마감 후(16:10)엔 브리핑이 자동으로 돌아갑니다.
**밤 11시~아침 7시(KST)는 호출하지 않고, 주말은 일요일 저녁 1회만** 점검(+ 데이터 최신화)합니다 — 잠자는 시간에 API 비용이 새는 것을 막기 위한 설계입니다.
첫 실행 때 5개년 과거 데이터(주가/환율/해외지수)와 백테스트 통계도 자동으로 채워지고, 이후 매주 일요일마다 갱신됩니다.

### 2단계. Vercel 배포 (내 전용 앱 만들기)

1. https://vercel.com 접속 → **Sign Up** → **Continue with GitHub** 로 가입
2. **Add New... → Project** 클릭
3. 목록에서 **invest** 저장소 옆의 **Import** 클릭
4. **Environment Variables** 항목을 펼쳐서 아래 항목을 추가:
   - Key: `ANTHROPIC_API_KEY` / Value: Claude 키 붙여넣기
   - Key: `GEMINI_API_KEY` / Value: Gemini 키 붙여넣기
   - (선택) Key: `DART_API_KEY` / Value: DART 인증키 붙여넣기
   - Key: `APP_PASSWORD` / Value: 원하는 비밀번호 (생략하면 기본 비밀번호 `0815`가 자동 적용됩니다. 더 안전한 값으로 바꾸고 싶으면 원하는 문자열로 설정하세요)
5. **Deploy** 버튼 클릭 → 1~2분 기다리면 완료 🎉
6. 완료 화면의 주소(예: `https://invest-xxx.vercel.app`)를 누르면 앱이 열립니다. 비밀번호 입력 화면이 먼저 나오며, `APP_PASSWORD`를 따로 설정하지 않았다면 **`0815`** 를 입력하면 됩니다.
7. **휴대폰에 앱처럼 설치**: PWA(설치형 웹앱)로 만들어져 있어 진짜 앱처럼 설치할 수 있습니다.
   - **안드로이드(크롬)**: 주소를 열면 몇 초 후 화면 하단에 **"앱 설치"** 배너가 자동으로 뜹니다. 안 뜨면 우측 상단 **⋮ 메뉴 → "앱 설치"** 를 누르세요. 설치하면 다른 앱들과 같이 홈 화면/앱 서랍에 아이콘이 생기고, 브라우저 탭이 아니라 독립된 앱처럼 실행됩니다. 이렇게 설치하면 브라우저의 "인터넷 사용기록 삭제" 같은 설정에 영향을 덜 받아 **입력한 자산 정보가 더 안정적으로 유지**됩니다.
   - **아이폰(사파리)**: 공유 버튼 → **"홈 화면에 추가"**

## 🎯 오늘의 작전 — 장세 적응형 엔진

모드를 사람이 고르지 않습니다. **엔진이 그날 장세를 판별해 작전을 바꿉니다.** 목적은 모드 구분이 아니라 어떤 장에서든 대응하는 것이기 때문입니다.

| 레짐 | 판별 조건 | 그날의 작전 |
|---|---|---|
| **폭락장** | 간밤 SOX -3.5%↓ / 코스피 -3%↓ / 보유 종목 -7%↓ | 폭락 반등 소액 매수 + 패닉 매도 방지 지침 |
| **급등과열** | 종목 +12%↑ 급등 | 추격 금지 + 내일 +3% 지정가 분할 익절 |
| **변동성확대** | 과반 종목이 변동성 높음/극단 | σ비례 눌림목 지정가 매수 |
| **보통** | 그 외 | 평상시 원칙 (눌림목 + 개별 종목 판단) |

### 폭락장에서 실제로 뭐가 통했나 (5개년 실측)

대폭락장 대응은 이번 라운드의 핵심이라 **"피하기"가 아니라 "먹기"까지** 데이터로 검증했습니다.

**① 폭락 다음날은 통계적으로 반등했다**

| 지표 | 결과 (n=81, -8%↓ 폭락일) |
|---|---|
| 익일 종가 수익률 | 평균 **+1.4%** · 상승확률 65% |
| 최근 6개월 급변동장 | 평균 **+2.1%** · 승률 64% |
| 2일 후 누적 | 평균 +2.8% · 상승확률 67% |
| 익일 시가→저가 | 평균 -4.0% (**장중엔 반드시 더 빠진다**) |

→ 규칙: **폭락 마감 동시호가에 소액 매수 → 익일 종가 청산.** 거래비용 차감 후 5년 누적 +153.7%.
→ 익절/손절을 미리 거는 변형은 **오히려 열위**(+3% 익절은 급변동장 반등을 잘라먹고, -6% 손절은 장중 진폭에 먼저 걸림)라 쓰지 않습니다.
→ 단, **13.6% 확률로 다음날 또 -8% 폭락**한 전례가 있어 총자산 10% 이내 소액이 전제입니다.

**② 갭하락 아침의 패닉 매도는 손해였다**

간밤 SOX -3.5%↓였던 395일 실측:

| 지표 | 결과 |
|---|---|
| 당일 갭(시가) | 평균 **-2.4%** (89%가 갭하락) |
| 시가→종가 | 평균 +0.27% |
| 시가 매도 후 -3% 재매수 vs 그냥 보유 | **-0.13%p (무익)** |

→ **낙폭은 이미 갭에 반영돼 있습니다.** 시가 투매는 손실 확정일 뿐이라, 엔진은 폭락장에서 이 통계를 근거로 패닉 매도를 말립니다(손절선 원칙은 그대로).

**③ 상한가 근처 급등 다음날은 장중에 팔아야 했다**

| 지표 | 결과 (n=50, +12%↑ 급등일) |
|---|---|
| 익일 고가 | 평균 **+5.4%** (전일 종가 대비) |
| 익일 고가가 +3% 도달 | **64%** |
| 익일 갭하락 출발 | 42% |

→ 규칙: **내일 아침 +3% 지정가 분할 매도를 미리 걸어둘 것.** 시가 매도(평균 갭 +0.7%)보다 유리하고, 42%가 갭하락이라 전량 홀드는 금물입니다.

### 눌림목 규칙 (변동성확대/보통 장세)

폭락 직후 종목 제외 → 변동성 상위 종목 → **현재가 -0.6σ 지정가** → +1.0σ 익절 / -0.8σ 손절. 지정가 미체결이면 **그날은 매매 없음**(추격 금지).

| 기간 | 누적 | 승률 | 최대 낙폭 |
|---|---|---|---|
| 급변동장 전반 | +21.0% | 67% | 8.6% |
| 급변동장 후반 | +7.1% | 54% | 18.5% |
| 2025년 | +4.3% | 43% | 20.5% |
| 2024년(평온) | +10.7% | 48% | 17.2% |

### 📐 국면별 조건부 전망 — "평균"이 아니라 "지금과 같았던 때"

**여러 장세를 뭉갠 평균은 미래 판단 근거가 될 수 없습니다.** 예를 들어 "최근 6개월 보유 수익률 +63%"라는 숫자에는 코스피가 2배 오른 강세장과, 그 뒤 고점 대비 40~60% 무너진 붕괴 국면이 함께 들어 있습니다. 강세장이 만든 평균을 붕괴 국면에 적용하면 정확히 반대로 판단하게 됩니다.

그래서 엔진은 **지금과 같은 상태였던 과거 시점만 골라** 그 다음 20거래일에 실제로 무슨 일이 있었는지를 분포로 보여줍니다(`data/scenarios.json`, `npx tsx scripts/build-scenarios.ts` 로 갱신).

| 국면 | 표본 | 20일 후 중앙 | 하위 25% | 손실확률 | -20%↓ | +20%↑ |
|---|---|---|---|---|---|---|
| 안정상승추세 | 1,486 | +2.7% | -3.1% | 37% | 2% | 15% |
| 고변동상승추세 | 1,220 | +2.6% | -4.9% | 42% | 5% | 22% |
| 흔들리는상승 | 484 | +2.5% | -6.2% | 42% | 5% | 17% |
| **조정국면**(고점-20%↓) | 393 | **-1.7%** | -10.0% | **56%** | 8% | 15% |
| **고점붕괴초기**(고점-20%↓·변동성급등) | 314 | **-0.4%** | -8.6% | **52%** | 9% | 10% |
| **폭락바닥권**(고점-35%↓·변동성극단) | 23 | +7.8% | **-18.6%** | 39% | **26%** | 17% |

상승 국면(손실확률 37~42%)과 조정·붕괴 국면(52~56%)은 뚜렷하게 다릅니다. 폭락바닥권은 중앙값이 높지만 **26% 확률로 20% 넘게 더 빠졌고 표본이 23회뿐**이라 방향을 확정하는 근거로 쓸 수 없습니다 — 화면에도 그렇게 표시됩니다.

### 과거 통계가 담지 못하는 것

AI 업황 둔화 우려, 전쟁·지정학 리스크, 환율 급등, 국채금리 변동 같은 **구조적 리스크는 과거 가격 분포에 반영돼 있지 않습니다.** 5년 데이터에 없던 사건이 오면 위 확률은 그대로 빗나갑니다. 화면과 프롬프트 모두 이 한계를 함께 표시하며, 뉴스 레이어(Gemini)가 이런 이슈를 별도로 수집해 판단에 반영합니다.

### 정직하게 밝히는 한계### 정직하게 밝히는 한계

- **"매일 최소 5% 수익"은 어떤 규칙으로도 불가능합니다.** 5종목 중 1개 이상이 하루 5%+ 움직인 날은 96%로 기회는 거의 매일 있었지만, 그 기회를 순진하게 추격한 전략(변동성 1위를 시가 매수)은 6개월 **-54%** 였습니다.
- 고정 % 파라미터 최적화는 학습 +36% → 검증 **-5.5%** 로 뒤집혔습니다(과적합). σ비례를 쓰는 이유입니다.
- 위 성적은 과거 재현이며 미래 보장이 아닙니다. **최대 낙폭 -20% 구간을 견딜 수 있어야** 씁니다.
- 폭락 반등 규칙은 **시장 전체 패닉**에만 유효합니다. 개별 악재(회계·소송 등)에는 적용되지 않습니다.

모두 `npx tsx scripts/validate-modes.ts` 로 재현 가능합니다.

| 시장 신용융자 잔고 | 금융투자협회(KOFIA) | 20일 대비 +15% 급증 시 감점 및 경고 — 빚투가 몰린 장에서 급락하면 반대매매가 하락을 증폭 | 신호 자동 비활성 |

### 상관 비중 한도 — "나눠 담았다"는 착시 제거

기존 규칙은 **종목당** 최대 비중 50%였습니다. 그러면 삼성전자 50% + SK하이닉스 50% = 100%가
"분산"으로 통과됩니다. 두 종목의 상관은 최근 6개월 **0.89** — 사실상 한 종목입니다.

그래서 상관 0.7 이상인 쌍은 **합산 비중을 총자산의 50%로 제한**합니다(`lib/volatility.ts`의
`computeCorrelationCap`). 한도를 넘으면 신규/추가 매수 수량을 깎거나 아예 매수를 막고,
이미 넘긴 보유는 위험 카드에 경고로 표시합니다.

**검증 결과** (`npx tsx scripts/validate-correlation-cap.ts`, 2천만원 기준·나머지는 현금)

| 합산 비중 | 누적수익(6개월) | 일변동성 | 최악의 날 | 최대낙폭 | 위험대비수익 |
|---|---|---|---|---|---|
| 40% | +34.9% | 2.52% | -5.6% (-112만원) | 22.3% | 1.57 |
| 50% | +43.7% | 3.15% | -7.0% (-140만원) | 27.3% | 1.60 |
| 100% | +83.3% | 6.30% | -14.0% (-280만원) | 48.7% | 1.71 |

> **정직하게**: 위험대비수익이 한도를 바꿔도 거의 그대로입니다(1.57~1.71). 즉 이 한도는
> **수익을 개선하는 규칙이 아니라, 최악의 날을 견딜 수 있는 크기로 묶는 생존 규칙**입니다.
> 실측 상관은 5년 0.72 → 최근 1년 0.84 → 최근 6개월 0.89로, 급변동장일수록 더 붙습니다.

### 자동 감시주문 — 조건부로만 권합니다

확인 시간이 불규칙하다는 전제에서, 손절 예약주문을 "무조건 필수"로 만들지는 **않았습니다**.
데이터가 그렇게 말하지 않기 때문입니다.

**검증 결과** (`npx tsx scripts/validate-watch-orders.ts`, 5년·5종목, 엔진과 동일한 ATR 손절)

| 못 보는 기간 | 구분 | 건당 평균 | 최악 | -10% 넘는 손실 비율 |
|---|---|---|---|---|
| 1거래일 | 예약 있음 | -0.27% | -19.1% | 0.4% |
| 1거래일 | 예약 없음 | -0.26% | **-17.8%** | 0.5% |
| 5거래일 | 예약 있음 | +0.23% | **-20.0%** | **2.4%** |
| 5거래일 | 예약 없음 | +0.60% | -34.0% | 4.8% |

- **하루 이상 못 보면 예약이 꼬리를 자릅니다** — 최악 -34.0% → -20.0%, 큰 손실 비율 절반.
- **당일 안에 다시 볼 수 있으면 오히려 불리했습니다** — 스톱을 스치고 되돌아와 손해 본 건(94회)이
  실제로 손실을 줄여준 건(66회)보다 많았고, 최악도 -17.8% → -19.1%로 나빠졌습니다.
- 어느 경우든 **건당 평균 수익은 예약 쪽이 낮습니다**. 그래서 앱은 "예약을 걸면 더 번다"가
  아니라 **"하루 이상 자리를 비울 때 크게 잃지 않기 위한 보험"**으로만 안내합니다.
- 참고: 제안된 `-2% 손절 / +3% 익절` 같은 고정 % 파라미터는 채택하지 않았습니다. 이전 검증에서
  고정 % 방식은 학습구간 +36% → 검증구간 -5.5%로 뒤집혔습니다(과적합). σ(변동성) 비례 손절만
  네 구간 모두 견뎠습니다.

$195.04 종목의 손절가가 $183(실제 $182.65)으로 나왔습니다.

검증: 5종목 × 예상경로 전 구간 **335개 가격 전부 주문 가능**, 손익비 1:2 유지 확인.

### 팔라는 종목에 "이 값에 사면"을 띄우지 않습니다

같은 QA에서 발견한 문제입니다. 예상 경로 카드가 종목 상태와 무관하게 렌더링돼, 엔진이
`손절`·`전량매도`를 권하는 종목에도 파란색 **"이 값에 사면"** 카드가 크게 떠 있었습니다.
지금은 매도를 권하는 종목이면 매수 지정가와 매수 체결확률 열을 숨기고, 그 이유를 명시합니다.

지금 상태를 10개 변수로 벡터화하고(전일 등락·3일/5일 누적·RSI·낙폭·이격도·변동성 분위·거래량Z·

**결과 (`npx tsx scripts/validate-analog.ts`, 워크포워드·미래정보 미사용)**

### 대신 제공하는 것 — 도달 확률 (지정가가 체결될까)

단타에서 실제로 필요한 판단은 "오를까?"가 아니라 **"내가 건 지정가에 닿을까?"**입니다.
이건 방향이 아니라 변동폭의 문제이고, 변동폭은 검증된 모델이 잘 맞힙니다(90% 구간 적중 88%).

**검증 결과** (`npx tsx scripts/validate-touch.ts`, 2,495일 실측 → `data/touch-stats.json`)

| 거리 | 이론값(반사원리) | 실측 하단 도달 | 실측 상단 도달 |
|---|---|---|---|
| 0.5σ | 61.7% | 46.9% | 53.6% |
| 0.75σ | 45.3% | 32.6% | 39.5% |
| 1.0σ | 31.7% | 22.6% | 28.6% |
| 2.0σ | 4.6% | 4.6% | 8.3% |

이론값이 실제보다 20%가량 높아(하루 한 세션만 열리고 갭으로 시작하는 실제 시장과 연속 랜덤워크
가정의 차이) **실측표를 그대로 씁니다**. 상단 도달률이 하단보다 일관되게 높은 건 국내 반도체주의
상방 꼬리가 더 두껍기 때문이며(상한가 현상), 앱은 이 비대칭을 평균으로 뭉개지 않고 따로 씁니다.

앱은 이걸 두 가지로 보여줍니다.
- **지정가 후보**: "이 값에 사면 / 이 값에 팔면" + 마감까지 닿을 확률 (0.75σ 거리 기준)
- **시간대별 표**: 30분 단위 예상 상·하단 금액과, 그 지정가에 **그 시각까지 한 번이라도 닿을 누적 확률**
  (10:00 조회 시 13:00까지 21% → 마감까지 33% → 다음 거래일까지 47%처럼 시간이 갈수록 올라갑니다)

### 예상 경로 차트 — 글 대신 그림으로

"예상 등락 -11.7% ~ +14.2%"라는 문장은 초보자가 감을 잡기 어렵습니다. 그래서 같은 추정을
**조회한 그 시각부터 오늘 마감 → 다음 거래일 → 2거래일 뒤**까지의 확률 구간으로 그립니다
(`lib/forecastPath.ts` 계산 → `app/ForecastChart.tsx` 렌더).

- 폭은 위 변동성 모델의 σ와 경험분위수를 그대로 씁니다. 불확실성은 시간에 비례해 쌓이므로 폭은 **√시간**으로 벌어집니다.
- 하루 안에서는 개장 직후·마감 무렵이 크고 점심때가 작은 **U자 분산 배분**을 씁니다. 그래서 15:20에 조회하면 "오늘 변동폭 4% 남음"처럼 남은 몫이 작다는 게 바로 보입니다.
- 중앙선은 예측이 아니라 "제자리 + 과거 같은 국면의 아주 약한 평균 흐름"(하루 ±0.5% 제한)입니다.
- 손절가·목표가를 같은 축에 겹쳐 그려서 **손절선이 하루 정상 변동폭 안에 있는지**를 눈으로 확인할 수 있습니다.

**검증 결과** (`npx tsx scripts/validate-forecast-path.ts`)

|---|---|---|---|
| 다음 거래일 | 88.3% | 48.0% | 1,235 |
| 2거래일 뒤 | 89.4% | 44.8% | 1,235 |

√시간 가정의 실측 비율(실제 h일 변동성 ÷ 이론값)은 0.87~1.04로, 랜덤워크 가정이 이 종목군에서 대체로 성립합니다.

**한계**

- 안쪽 50% 띠는 표시보다 살짝 좁게 잡힙니다(하루 기준 분위수를 여러 날에 그대로 쓰기 때문). 앱의 `분석 방식` 탭에도 이 숫자를 그대로 공개합니다.
- 장중 U자 배분은 자체 수집 로그 표본이 20건뿐이라 **실측이 아니라 통상적으로 관찰되는 표준 형태**입니다. 그래서 장중 부분구간은 일 단위만큼 검증되지 않았습니다.
- 주말·공휴일에는 장중 구간을 그리지 않고 거래일 단위만 표시합니다.
- 이 데이터는 **Claude 프롬프트에 넣지 않습니다** — 순수 파생값이라 토큰을 쓸 이유가 없습니다(차트 추가 토큰 비용 0).

> **채택하지 않은 변수**: VIX는 이론상 선행지표지만 실측 기여도가 0이어서 넣지 않았습니다. GARCH(1,1)는 EWMA보다 열위였습니다. 2요소·비대칭 모델은 복잡도만 늘고 개선이 없어 버렸습니다.

**한계 (정직하게)**

- 90% 구간 적중률이 목표보다 1~2%p 낮습니다. 원인은 **레짐 전환 시점**입니다 — 조용하던 종목이 갑자기 급등락하기 시작하는 첫날은 어떤 사후 관측 모델도 맞히지 못합니다. 그래서 경계값은 보수적으로 해석하세요.
- 상방 초과(6.8%)가 하방 초과(4.5%)보다 많습니다. 지금은 급등 쪽 꼬리가 더 두꺼운 국면이라, 성급한 매도나 공매도가 특히 불리합니다.
- 확정 예측이 아니라 "이 정도 범위는 각오해야 한다"는 기준입니다.

**포트폴리오 위험 (내 계좌 금액 기준)**

종목별 %가 아니라 **내 돈이 하루에 얼마나 흔들리는지**를 원 단위로 보여줍니다. 이때 종목 간 상관관계를 반영하는 것이 핵심입니다 — 실측상 삼성전자와 SK하이닉스의 상관계수는 **0.86**으로, 둘을 나눠 담아도 분산 효과가 거의 없습니다.

- 3종목에 균등 분산해도 **실질 독립 종목수는 약 1.2개** (사실상 한 종목 베팅)
- 종목별 위험을 단순히 더하면 실제 위험을 **53% 과소평가**
- 화면에는 "20일에 한 번 겪는 나쁜 날", "100일에 한 번 오는 최악의 날"을 금액으로 표시

## ❓ 자주 묻는 질문

**Q. 자동으로 주식을 사고 파나요?**
아니요. 이 에이전트는 **조언만** 합니다. 실제 매매는 본인이 증권사 앱(MTS)에서 직접 합니다. 자동 매매는 증권사 API 인증·법적 요건이 필요해 의도적으로 제외했습니다.

**Q. 비용이 얼마나 드나요?**
GitHub Actions·Vercel은 무료 한도로 충분합니다. **Gemini**는 자동 수집(15분 간격, 하루 약 27회)만 실제로 호출하고 — 화면에서 "AI 정밀 분석"을 눌러도 그 결과가 20분 이내로 신선하면 그대로 재사용하고 새로 호출하지 않습니다 — 프롬프트도 짧게, 응답도 뉴스 15건으로 제한해 호출당 토큰을 최소화했고 가장 저렴한 flash-lite/flash 모델을 우선 사용하므로, 소액(만 원 안팎) 충전으로도 상당 기간 충분합니다. 다만 정확한 소진 속도는 실제 사용 패턴에 따라 다르니, https://aistudio.google.com 좌측 하단 **사용량/결제** 메뉴에서 주기적으로 잔액을 확인하세요. **Claude API**는 사용량 과금인데, 자동수집은 저렴한 모델(Haiku)로 장중 15분 간격 + 개장전/마감 브리핑만 돌고 밤 11시~아침 7시·평일 외에는 호출하지 않도록 설계해 자동수집만으로는 월 $2~4 수준입니다. 여기에 화면에서 직접 누르는 "AI 정밀 분석"(고급 모델) 호출 비용이 하루 몇 회 기준으로 더해져도, 합계는 **월 $10 이내**를 목표로 설계했습니다. 다만 이는 예상치이며 실제 사용 패턴에 따라 달라질 수 있으니, [console.anthropic.com/settings/billing](https://console.anthropic.com/settings/billing)에서 **월 지출 한도(Spending limit)를 직접 설정**해두는 것을 강력 권장합니다 — 앱 코드로는 API 자체의 과금을 막을 수 없기 때문입니다.

**Q. 시세가 실시간인가요?**
국내 5종목(삼성전자·SK하이닉스·한미반도체·삼성전기·DB하이텍)의 개별 시세는 네이버 금융의 실시간 폴링 API를 우선 사용해 지연이 짧은 편입니다(네이버가 실패할 때만 야후로 폴백). 엔비디아는 네이버에 데이터가 없어 야후 파이낸스 API를 바로 사용합니다. 코스피·나스닥·SOX·환율 등 **매크로/해외지수도 야후 파이낸스 API를 쓰기 때문에 최대 15~20분 지연**될 수 있습니다. 화면에 시세 옆 "n분 전 시세"로 표시됩니다. 어느 경우든 증권사 실시간 호가·체결과 완전히 같지는 않으니, 실제 주문 직전에는 반드시 증권사(국내/해외) 앱에서 최신가를 확인하세요. 이 한계 때문에 진입/무효화 조건을 고정 가격이 아니라 "조건 충족 여부"로 설계했지만, 완전한 실시간 체결가는 증권사 API 인증 없이는 얻을 수 없어 완전히 없앨 수는 없습니다.

**Q. 알림(카카오톡 등)은 없나요?**
현재는 없습니다. 자동수집은 장중 15분 간격으로 데이터만 쌓고, 실제 조언은 앱에서 버튼을 눌러야 받을 수 있습니다. 장중에는 주기적으로 앱을 열어 확인하는 것을 권장합니다.

**Q. 자동 수집 데이터는 어디에 쌓이나요?**
이 저장소의 `data/` 폴더에 자동 커밋됩니다. `data/latest.json`(최신), `data/log/날짜.json`(일별 기록), `data/market-history.json`(5개년 주가/환율/지수), `data/backtest.json`(백테스트 통계, 매주 갱신)입니다.

**Q. 앱 분석과 자동 수집의 차이는?**
자동 수집(장중 15분 간격)은 시장 전체 관점의 신호와 뉴스를 축적하고, 앱에서 버튼을 누르면 **내 보유 현황을 반영한** 맞춤 분석이 그 자리에서 실행됩니다.

**Q. 백테스트는 얼마나 믿을 수 있나요?**
룰 엔진의 일봉 기술적 점수가 68점 이상이었던 과거 시점을 찾아 5/10거래일 후 종가 수익률을 집계한 **단순 참고 통계**입니다. 장중 변동성·뉴스·매크로는 과거 시점으로 재현할 수 없어 제외했고, 실제 체결가·슬리피지·거래비용도 반영하지 않았습니다. "과거 승률 OO%"는 통계적 경향일 뿐 다음 매매의 결과를 보장하지 않습니다 — 화면과 AI 판단 모두 이 통계를 절대적 근거로 쓰지 않고 참고 지표로만 언급하도록 설계했습니다.

**Q. 코드를 수정하면 어떻게 반영되나요?**
GitHub에서 파일을 수정(커밋)하면 Vercel이 자동으로 다시 배포합니다. 별도 조작이 필요 없습니다.

## ⚠️ 알려진 한계 (정직하게 밝힙니다)

- **시세 지연**: 국내 5종목은 네이버 실시간 API를 우선 써서 지연이 짧은 편이지만, 엔비디아와 매크로/해외지수(코스피·나스닥·SOX·환율·유가 등)는 야후 무료 API 특성상 최대 15~20분 지연 가능합니다. 어느 쪽도 증권사 실시간 호가·체결 데이터는 아닙니다.
- **엔비디아 데이터 한계**: DART 전자공시·KRX 외국인/기관 수급은 한국 거래소 전용 데이터라 엔비디아에는 적용되지 않습니다(뉴스·기술적 지표·매크로로만 판단). 5개년 백테스트 통계도 국내 종목보다 늦게(주간 갱신 주기 기준) 채워질 수 있습니다.
- **급등락 표시 안전장치**: 지수·환율 등의 등락률이 상식적으로 불가능한 수준(예: 지수가 하루 10% 이상)으로 계산되면, 데이터 오류로 간주해 등락률을 0%로 보정하고 서버 로그에 경고를 남깁니다(잘못된 급등락을 그대로 보여주는 것보다 안전). 다만 이 안전장치가 실제로 발생 가능한 극단적 이벤트(예: VIX 급등)까지 지우지 않도록 종류별로 다른 상한선을 적용했습니다.
- **분석 소요 시간**: AI 정밀 분석은 30초~2분이 걸립니다. 그 사이 가격이 움직일 수 있어, 결과는 고정가가 아니라 조건부 트리거 중심으로 제시됩니다.
- **백테스트는 단순 재현치**: 5개년 일봉 종가만으로 재현한 참고 통계이며, 장중 변동성·뉴스·매크로·거래비용·슬리피지는 반영하지 않았습니다. 과거 승률이 미래 수익을 보장하지 않으며, 검증된 필승 전략이 아니라 확률적 우위를 노리는 참고 지표입니다.
- **공휴일 인식 제한**: 양력 고정 공휴일(신정·삼일절 등)만 자동 인식합니다. 설날·추석 등 음력 공휴일 주간은 별도로 확인하세요.
- **비밀번호는 정식 인증이 아님**: 기본값(`0815`) 또는 직접 설정한 `APP_PASSWORD` 값 하나로 여닫는 단일 비밀번호 게이트일 뿐, 계정별 권한 관리나 무차별 대입 공격 방어 같은 정식 인증 시스템이 아닙니다. 배포 주소를 다른 사람과 공유하지 말고, 가능하면 `APP_PASSWORD` 환경변수를 본인만 아는 값으로 바꾸는 것을 권장합니다.
- **공포탐욕지수**: 미국 시장(CNN) 기준 지표이며 비공식 데이터 소스라 수집이 실패할 수 있습니다(실패 시 조용히 생략).
- **외국인/기관 수급은 실시간이 아니라 전일까지 확정된 EOD 데이터**: KRX 공식 공개 데이터를 쓰지만, 장중 실시간 체결 기준 수급(초 단위로 바뀌는 수급 주체별 매매)까지는 증권사 API 인증 없이는 가져올 수 없어 제외했습니다. "전일 기준"이라는 점을 감안해서 참고하세요. 데이터를 못 가져온 종목은 거래량Z점수(거래량 급증 여부)로 대신 설명합니다. KRX 공개 엔드포인트는 공식 문서화된 API가 아니라 리버스 엔지니어링된 방식이라, 사용 중 예고 없이 응답 형식이 바뀌면 해당 종목만 조용히 "데이터 없음"으로 처리됩니다(에러로 앱이 멈추지 않음).
- **DART 공시 sentiment는 제목 키워드 기반 단순 분류**: 공시 본문 전체를 분석하는 것이 아니라 "유상증자"·"자기주식취득" 같은 제목 키워드로만 긍/부정을 1차 분류합니다. 최종 해석은 Claude가 맥락을 더해 판단하지만, 애매한 공시는 반드시 원문 링크를 눌러 직접 확인하세요.
